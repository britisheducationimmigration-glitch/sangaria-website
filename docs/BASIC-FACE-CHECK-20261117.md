# Basic face and blink check

When Require selfie is enabled, employee IN, OUT and half-day OUT now run a browser-side MediaPipe face-landmark check before capturing the stored selfie. The sequence is eyes open, both eyes closed, eyes reopened across fresh video frames. No head turn is required. A wink alone is insufficient; prolonged eye closure resets the check. Zero/multiple faces reset progress. A small face, missing landmarks, hidden page, camera interruption or 15-second challenge timeout blocks completion. Instructions appear beside the camera as well as on the active button. The detector closes after success/failure.

Model and WASM/code assets load from pinned public Google/jsDelivr URLs. Camera frames are processed locally; these asset hosts receive download requests, not employee photos. The captured selfie continues to be stored by the existing attendance server. Model loading failure blocks submission. Initial use requires internet and downloads model assets.

The server requires photo bytes and the basic-check flag when Require selfie is on. This flag is client-reported and can be forged: this is NOT trusted server liveness, face identity matching or replay/deepfake protection. Existing GPS, PIN and device checks continue. Admin manual corrections and break actions retain their existing behavior. Require selfie OFF explicitly disables this policy; enable it in Employees & Office GPS for this check to apply.

Verification: typecheck, pure landmark rejection tests and existing server checks. MySQL regression checks that a supplied image without the basic check is refused. Physical-device validation remains necessary: Android Chrome/iPhone Safari; empty chair; two faces; straight-only; normal blink, wink, eyes closed from start; low light; permission denial; interrupted camera; model-download failure; IN/OUT/half-day OUT. Basic motion may be spoofed by a suitable video and must not be represented as certified liveness.
